# 마지막 실행과 이해 확인
완료 보고 전에 upstream/verification-before-completion.md의 증거 원칙을 적용하십시오.
원문의 Git push/PR 예시는 게시 허가가 아닙니다. 시험 작업물의 외부 push는 금지하십시오.
red/green 확인은 소유한 테스트·안전한 연습 변경에서만 하고 보호된 테스트나 채점 자료는 바꾸지 마십시오.

## 결과 후보 고정
새 기능·의존성 추가를 중단하고 중요한 결함에 집중하십시오. 늦게 바뀐 결정은 다시 설명하십시오.
요구사항별 상태와 실제 근거를 확인하고, 미검증을 실패도 성공도 아닌 미검증으로 표시하십시오.

## 실행 환경
제출 형식과 실제 실행 명령을 과제 안내에서 확인하십시오.
Docker가 필요하면 초반부터 준비하고 새 이미지 빌드·컨테이너 기동·대표 API/사용자 동작을 실행하십시오.
Dockerfile 존재만 확인한 경우 실행 성공이라고 말하지 마십시오. Docker가 없으면 미검증으로 보고하십시오.
정확한 제출 구성·실행 명령은 당일 안내를 따릅니다. 실행 담당자는 초반부터 지정 경로를 실제로 확인하고, 마지막 제출 후보의 버전과 검증 근거를 연결합니다.
로컬 절대 경로·누락 파일·초기 데이터·포트·환경변수·권한·외부 다운로드 의존을 확인하십시오.
외부 서비스와 결제·인증 설정은 임의로 만들지 마십시오. 제출은 지정된 플랫폼 방법만 사용하십시오.

## 사람에게 넘길 내용 (간결하게)
1. 실제 핵심 동작과 코드/데이터 흐름.
2. 중요한 선택·이유·한계: 비교 측정과 추정을 구분.
3. AI가 실행한 검증: 명령·결과·버전.
4. 사용자가 실제로 확인한 행동과 관찰: 발언/기록 근거.
5. 남은 문제·미검증·운영 한계.

## 이해 확인과 독립 답변
핵심 동작/방법 선택/업무 규칙/무결성/직접 검수/실행 한계의 6개 영역에서 실제 사실을 짧게 점검하십시오.
모르는 항목은 실제 사례로 설명하되, 대안이나 이유를 뒤늦게 지어내지 마십시오.
사용자가 자기 말로 설명하도록 돕고 제출용 1인칭 답변을 만들어내지 마십시오.
독립 평가 단계에서 AI 사용이 금지되면 지원을 중단하고 기록 외부 반출도 하지 마십시오.
`TEAM_PROTOCOL.md`에 따라 오케스트레이터·작업 세션·백그라운드 자동화의 실제 중단을 확인합니다. 인계 파일의 done/stopped는 ACK이며 물리적인 종료 증명이 아닙니다. 확인되지 않은 세션이 있으면 중단 완료라고 보고하지 않습니다.
답변에 필요한 시간은 새 기능 개발로 대체하지 마십시오.
