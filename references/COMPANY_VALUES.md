# 회사 가치를 제품 경험으로 연결하기

회사의 가치는 로고·색·문구와 함께 **사용자가 대우받는 방식, 업무의 명확성, 정보의 신뢰성, 제품의 완성도**에서 드러나야 합니다. 사용자가 자기 조직의 제품으로 신뢰하고 자부심을 느낄 경험을 설계하십시오.

## 실제 과제에서 적용할 순서

1. 당일 자료와 허용된 공식 출처에서 대상 회사·제품의 가치, 행동 원칙, 브랜드 기준을 확인합니다. 출처·발행 시점·적용 조직을 기록하고, 서로 다른 계열사의 기준이나 과거 버전을 섞어 단정하지 않습니다. 네트워크가 허용되지 않으면 제공된 자료 범위에서 확인합니다.
2. 과제와 직접 관련된 핵심 가치부터 고릅니다. 각 가치를 **공식 근거 → 해당 사용자에게 줄 경험 → 제품 동작/화면/문구 → 확인 가능한 완료 기준**으로 연결하여 `.sprint/CONTRACTS.md`에 기록합니다.
3. 사용자 UI와 운영자 UI 담당이 이 기준을 공유합니다. UX 검토자는 실제 업무 목표를 수행해 그 경험이 드러나는지 확인하고, 2번 구현 해설 담당은 선택 이유와 실제 근거를 사용자에게 설명합니다.
4. 가치 문구를 화면에 반복 노출하는 것만으로 반영했다고 평가하지 않습니다. 기본 화면에는 사용자의 현재 업무가 우선이며, 가치와 구현의 상세 연결은 설계 기록과 해설에서 다룹니다.

## 공개 자료의 예: SK하이닉스 New CoC

SK하이닉스가 공개한 New CoC 소개는 “초기술로 세상을 더 행복하게”라는 핵심 가치와 여섯 행동양식을 설명합니다. 원문은 구성원의 행동 원칙이며, 아래 제품 기준은 **과제 맥락에 맞게 적용하기 위한 설계 해석**입니다. 공식 UI 규격이나 대회 채점표를 뜻하지 않습니다.

| 공개 자료의 행동양식 | 제품에서 확인할 설계 해석 |
| --- | --- |
| Customer Focus | 사용자의 맥락과 다음 행동을 먼저 파악하고, 필요한 정보·예방·오류 회복을 적시에 제공한다. |
| Data Driven | 사용자의 판단에 필요한 데이터 기준·갱신 상태·추정과 확정의 차이를 신뢰할 수 있게 전달한다. |
| One Team | 사용자·운영자 흐름이 같은 용어와 상태로 이어지고, 분업 결과가 하나의 일관된 제품으로 작동한다. |
| Bar Raising | 필수 업무를 높은 완성도로 마친다. 정보 구조·문구·시각 체계와 사용성에 명확한 완료 기준을 둔다. |
| Perfection | 오류·빈 상태·경계·복구·접근성을 포함한 디테일을 검증하고, 어려운 상황에서도 결과와 상태가 일관되게 전달되도록 한다. |
| Innovation | 과제의 실제 불편과 제약을 확인하고, 더 나은 방법을 시험한 근거로 개선한다. 기능 추가 자체를 혁신이라고 부르지 않는다. |

특히 원문의 메모리 기술 혁신 맥락을 작은 글자·작은 버튼·무조건 많은 데이터 보관 같은 UI 규칙으로 직역하지 마십시오. 모든 가치를 억지로 기능에 붙이지 말고, 관련성 있는 연결과 실제 검증을 남깁니다. 다른 회사/주제의 과제에서는 그 대상의 확인된 기준을 적용합니다.
