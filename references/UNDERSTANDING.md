# 개발 중 이해와 실제 근거를 축적하기

사용자가 마지막에 처음 구현 선택을 알게 하지 마십시오. 허용된 개발 시간에 중요한 선택을 짧게 설명하고, 코드·실행·직접 관찰을 연결합니다. 문항 수나 실제 출제 내용을 고정하지 않습니다.

## understanding 담당의 책임

오케스트레이터의 완료 보고만 받아 설명하지 말고 실제 변경과 실행 근거를 확인합니다. 사용자의 대화 창구는 오케스트레이터 하나로 유지하고, 짧은 설명·직접 검수 목표·오해 발견을 그 창구로 전달합니다. 사용자에게 여러 작업자의 장문 보고를 읽게 하지 않습니다.

중요한 선택을 할 때는 **선택 / 이유 / 실제 대안과 한계 / 확인 계획 / 필요한 사용자 판단**을 다섯 줄 안팎으로 제시합니다. 측정하지 않은 우월성이나 하지 않은 대안 비교를 만들지 않습니다. 보통의 함수·파일·스타일 수정은 합의된 범위에서 자율 진행합니다.

## 기록할 이해 영역

다음은 답안 양식이나 예상 문제 목록이 아니라 빠뜨리지 말아야 할 이해 관점입니다.

| 관점 | 남길 실제 사실 |
| --- | --- |
| 핵심 흐름 | 실제 입력이 어떤 처리와 화면·결과로 이어지는지 한 사례 |
| 방법 선택 | 목적·제약, 선택한 방법, 고려/시험한 대안의 구분, 보장하지 못하는 것 |
| 업무 의미와 예외 | 확인한 정의·범위·우선순위, 현업 역할에서 받은 답과 적용 위치 |
| 입력 무결성과 변경 | 오류 발견·차단·복구, 재계산·갱신·이전 결과 보존을 확인한 근거 |
| 사용자 직접 검수 | 사용자가 실제 한 조작·관찰·판단; 아직 안 한 것은 미확인 |
| 실행과 한계 | 지정 환경에서 실제 실행한 명령·결과·버전, 미실행·미확인 사항 |

핵심 체크포인트에서만 사용자에게 한 문장으로 이해를 확인합니다. 답을 유도하거나 형식적인 동의를 이해 확인으로 취급하지 않습니다. 사용자가 핵심 업무 1~2개를 직접 수행하도록 하고, AI 검사를 모두 반복하게 하지 않습니다.

## 섞지 말아야 할 증거

- **구현 사실**: 코드 위치와 해당 버전.
- **AI 실행 확인**: 명령, exit code, 관찰한 출력과 대상 버전.
- **독립 검토**: 구현 문맥과 분리된 검토자가 받은 목표, 접근 수준, 실제 관찰.
- **사용자 직접 검수**: 실제 사용자 행동과 발언. 제안한 조작은 수행한 조작이 아닙니다.
- **사용자 판단/이해**: 실제 발언이나 되말하기. 설명을 들음·승인함·이해함은 구분합니다.
- **가정/미검증**: 확인할 사항과 영향. 성공이나 실패로 꾸미지 않습니다.

기록은 현재 과제의 `.sprint/DECISIONS.md`, `.sprint/UNDERSTANDING.md`, 역할 인계 파일에 둡니다. 제품 화면에는 현재 사용자에게 필요한 업무·오류 회복 정보를 남기고, 개발 이유·원본 로그·검증 건수 나열을 기본 화면에 붙이지 않습니다.

## 서술형 전환

당일 규정에서 AI 지원을 허용한 개발/정리 단계에 실제 근거와 남은 한계를 정리합니다. 사용자가 하지 않은 판단을 1인칭으로 만들거나 실제 문항의 정답을 미리 재현하지 않습니다. AI 금지 독립 답변 단계에서는 오케스트레이터·작업 세션·자동화를 중단하며, 이후 답변 작성·교정·추가 자료 생성도 하지 않습니다. 단계 규정이 불명확하면 가정으로 AI를 계속 쓰지 말고 해당 규정을 확인합니다.
