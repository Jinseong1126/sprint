# 데이터·업무·계산 검증
과제마다 안내와 현업 응답으로 실제 의미를 확인하십시오. 이름만 보고 예외 정책을 추정하지 마십시오.
직접 확인할 업무 의문과 구현 선택을 구분하여 현업 역할에 코드 구현법을 요청하지 마십시오.

- 기준 데이터: 파일·필드 관계, 식별자, 중복, 필수값, 범위, 참조 무결성, 충돌 시 권위 있는 출처.
- 시간: 업무 기준일과 실제 timestamp·timezone·기간 양 끝 포함 여부를 구분. 예외 우선순위, 날짜 경계는 실제 규칙으로 결정.
- 계산: 목적(무엇을 줄이거나 늘리는가), 반드시 지킬 제약, 성공 기준, 실행 예산, 결정성/재현성을 분리.
- 방법 선택: 빠른 휴리스틱, 분할·군집, 제약 최적화 등은 역할이 다를 수 있음. 실제 요구사항과 근거로 비교하고 전역 최적이라고 과장하지 않음.
- 오류: 차단 오류와 경고를 구분. 잘못된 입력은 부분 성공으로 숨기지 않음. 재생성 실패가 이전 유효 결과를 훼손하지 않는지 확인.
- 입력 변경: 변경이 관련 수요·집계·배정·결과 버전에 반영되는지 확인. 출력 모양이 반드시 바뀌어야 한다고 가정하지 않음.
- 상태: 결과가 어느 입력/규칙 버전의 것인지 표시. 오래된 결과를 최신 성공으로 보이지 않음.
- 권한: 직접 API 접근에서 역할 제한 확인. UI에서 버튼을 숨기는 것만으로 보장하지 않음.
- 테스트: 정상, 빈/잘못된/경계, 같은 입력 반복, 순서 변경의 의미, 조건 변경, 실패 후 복구, 회귀를 위험도에 맞게 선택.
- 시각/시간 테스트: 앱 안의 테스트용 clock 주입을 활용하고 OS/감독 환경의 시각은 변경하지 않음.
- 검증 명령과 exit code, 관찰 결과와 해당 소스 버전을 연결. 실행 불가·외부 접근 제한은 미검증으로 표기.

최초 요구사항을 각 항목별 충족/미충족/미검증으로 매핑하십시오. 테스트 통과와 요구사항 전체 충족을 분리하십시오.
