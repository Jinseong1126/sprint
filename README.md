# 멀티 에이전트 개발 워크플로

대회 터미널의 **실제 과제 폴더**에서 첫 Codex의 **대화창**에 입력하십시오:

```text
$skill-installer Jinseong1126/sprint 설치하고 시작
```

새 팀에서는 이 **설치 세션이 오케스트레이터**가 됩니다. 설치 후 같은 세션에서 `SKILL.md`와 `references/COMPETITION_START.md`를 읽고 현재 과제의 안내·시간·규정·제출 조건을 확인한 뒤 팀 준비와 첫 실제 통합 계획으로 이어갑니다. 기존 팀이 있으면 현재 역할과 실제 세션 상태를 확인하며, 활성 오케스트레이터의 역할을 임의로 넘겨받지 않습니다. 주제별 답안이나 과거 과제 구현을 가져오는 도구가 아닙니다.

**2번째 세션을 먼저** 같은 프로젝트에서 다음과 같이 시작하십시오:

```text
구현 해설 담당으로 합류해줘.
```

2번의 해설 역할 등록이 확인된 뒤, **3~10번째 개발·검증 세션**은 다음과 같이 참여합니다:

```text
개발 워커로 합류해줘.
```

1번은 팀 운영·통합·진행·제출을 조율합니다. **사용자는 2번과 직접 대화하며** 구현 이유·대안·한계·실제 검증을 이해하고 직접 검수할 내용을 확인합니다. 2번은 실제 코드와 실행 근거를 확인하고, 사용자의 판단·관찰·수정 요청을 1번으로 전달합니다. 같은 이야기를 사용자가 양쪽에 반복 전달할 필요가 없도록 합니다.

기본 계획은 **총 약 10세션(오케스트레이터 1 + 구현 해설 1 + 개발·검증 워커 8)**입니다. 사용자가 여는 별도 터미널과 native 서브에이전트를 중복으로 10개씩 만들지 않습니다. 실제 생성·메시지·공유 파일 기능과 제공 한도 안에서 하나의 역할 명단으로 운영합니다. 스킬이나 역할 등록 helper가 터미널·에이전트를 직접 생성하는 것은 아닙니다.

`sprint`는 짧은 설치 주소와 내부 식별자로 유지합니다. 개발 용어 sprint는 정해진 짧은 기간에 목표를 수행하는 작업 주기를 뜻하며, 대회의 공식 명칭이 아닙니다. 이 구성 전체는 **멀티 에이전트 개발 워크플로**로 부릅니다.

같은 사용자 홈/환경을 공유하는 세션은 한 번 설치한 스킬을 사용할 수 있습니다. 별도 컨테이너라면 해당 환경의 설치·공유 범위를 확인합니다. 현재 자료를 읽고 역할·계약·인계·실행·사용자 이해를 연결하는 절차가 포함되어 있어, 사용자가 긴 운영 지시문을 다시 설명할 필요가 없습니다.

개발 요청에는 자동 선택을 허용하며, 반드시 이 스킬을 지정하고 싶으면 `$product-sprint`를 쓸 수 있습니다. 자동 선택은 모델이 요청 내용에 따라 결정합니다.

## Codex 설치 안내

이 저장소는 앱이나 전체 개발 프로젝트가 아니라 **스킬 하나**입니다.
- GitHub 저장소: `Jinseong1126/sprint`
- 스킬 루트: `.` (`SKILL.md`가 저장소 최상위에 있음)
- 설치할 스킬 이름: `product-sprint`
- 제공된 `skill-installer`의 설치 helper를 사용하십시오. 필요한 인수는 `--repo Jinseong1126/sprint --path . --name product-sprint --method download`입니다.
- 실제 Codex의 사용자 스킬 경로를 먼저 확인하고 필요한 경우 helper의 `--dest`로 지정하십시오. 현대식 사용자 경로는 `~/.agents/skills`; 구형 경로는 실제 지원이 확인될 때만 사용하십시오.
- `product-sprint`가 이미 설치되어 있으면 `SOURCE.json`에 나열된 **현재 런타임 파일 전체**의 존재와 해시를 비교하십시오. 이전 판의 일부 파일만 같다고 최신 설치로 보고하지 않습니다. 모두 같으면 기존 설치를 유지하고, 다르면 사용자 변경일 수 있으므로 무조건 덮어쓰거나 중복 설치하지 말고 누락/차이와 필요한 업데이트를 보고하십시오.
- Codex 버전·보안 설정·전역 지침 파일은 변경하지 마십시오. 다운로드나 설치가 금지된 환경에서는 제한을 우회하지 마십시오.
- 공개 아카이브 다운로드로 설치하며 Git 이력을 스킬 안에 복사하지 마십시오. 다운로드 실패를 보안 제한 우회의 근거로 삼지 마십시오.
- 설치 후 실제 Codex 스킬 목록에서 `product-sprint` 인식을 확인하십시오. 목록에 나타나지 않으면 현재 작업을 저장한 뒤 새 세션에서 확인하십시오.

## 설치 세션에서 시작으로 이어가기

사용자가 위처럼 설치와 시작을 함께 요청했다면 **설치 확인만 하고 종료하지 마십시오.** 설치된 경로의 `SKILL.md`, `references/COMPETITION_START.md`를 직접 읽어 같은 세션을 오케스트레이터로 이어갑니다. 첫 보고는 과제 목표·확인된 시간/규정·실제로 가능한 역할 배정·첫 통합 목표·필요한 사용자 판단으로 짧게 합니다.

설치만 요청했거나 현재 폴더가 실제 과제 폴더인지 확인되지 않은 경우, 이 문서만으로 개발 권한을 추가하지 않습니다. 준비물/스킬 폴더·사용자 홈·파일시스템 루트에서 앱을 만들지 않습니다. 한 항목의 위치 확인이면 충분하다면 긴 설문을 요구하지 마십시오.

## 팀·품질·이해

- **팀 운영**: `references/COMPETITION_START.md`, `TEAM_PROTOCOL.md`; 프로젝트별 `.sprint`에 역할과 인계·계약·현재 검증 상태를 기록합니다.
- **제품 품질**: 사용자 업무·명확한 주행동·상태·오류 회복을 우선합니다. 개발 로그와 내부 데이터는 제품 기본 화면과 분리합니다. 독립 UX 검사와 기능 QA, 실제 제출 환경 실행을 따로 확인합니다.
- **회사 가치**: 공식 자료의 가치·행동 원칙을 사용자 경험·제품 동작·화면·문구·완료 기준으로 연결합니다. `references/COMPANY_VALUES.md`에 공개 원문을 바탕으로 한 적용 예와 출처를 둡니다. 해당 조직의 기준과 과제 맥락을 확인하며, 장식적인 가치 문구만으로 반영했다고 판단하지 않습니다.
- **구성원 경험**: 매일 쓰는 구성원용 화면에서는 자신의 기여를 존중·감사받고 일의 가치·자부심을 느낄 수 있도록 UI 담당자가 시각 방향과 문구를 능동적으로 설계합니다. 공식 슬로건·가치 문구와 새로 작성한 인사·감사 표현을 구분하며, 사용 상황과 업무 정보에 조화시킵니다. 구성원에게 행동 원칙을 요구하는 것으로 대신하지 않습니다.
- **사용자 이해**: 2번 구현 해설 담당이 중요한 선택과 실제 대안·한계·실행 근거를 결정 시점에 사용자와 직접 설명·대화하고, 실제 직접 검수·판단만 기록합니다. 구현 종료 후 처음 이유를 알려주지 않습니다.
- **규정과 단계**: 당일 규정을 우선합니다. 문항 수·배점·답변 시간을 고정하지 않습니다. AI 금지 독립 답변 단계가 있으면 전체 AI 세션과 백그라운드 작업의 실제 중단을 확인합니다.
- **공개 범위**: 이 저장소에는 범용 지침·협업 보조 도구·합성 테스트만 둡니다. 과제 문제·자료·화면·제출 앱·작업 이력을 공개 저장소로 보내지 않습니다. 활용 기간에는 대회에서 정한 공개 유지 조건을 따릅니다.

`scripts/session_board.py`는 Python 표준 라이브러리만 쓰는 로컬 역할·인계 보조 도구입니다. 세션 생성·실제 메시지·프로세스 종료를 수행하지 않습니다. Python이나 브라우저가 없으면 제공된 허용 도구로 대체하고 실제 미검증 사항을 구분합니다.
